# WORKFLOW

Этот файл фиксирует рабочий процесс разработки бота, чтобы не повторять договоренности в новых сессиях.

## Базовый процесс

1. Пользователь формулирует задачу по изменению бота.
2. Codex вносит изменения локально в проект.
3. Проверка выполняется в stage-режиме через `.env.stage`.
4. Пользователь проверяет поведение в тестовом чате.
5. После подтверждения (`ок в прод`) изменения отправляются в `main`.
6. GitHub Actions деплоит на сервер и перезапускает `tg-poll-bot`.
7. Codex проверяет systemd и прикладной health-check.

## Правила безопасности

- Новые и рискованные изменения сначала проверяются в stage.
- Прод-бот обычно не останавливается во время разработки.
- Не запускать два экземпляра с одним и тем же токеном одновременно.

## Команда запуска stage локально

```bash
make setup
./run_stage.sh
```

## Быстрый промпт для новой сессии

"Работаем по WORKFLOW.md: сначала stage-тест, потом после моего подтверждения в прод."
