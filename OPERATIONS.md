# Эксплуатация Telegram-бота

## Локальная проверка

```bash
make setup
make lint
make test
make stage
```

Stage должен использовать отдельные `BOT_TOKEN`, `CHAT_ID` и `DATA_DIR` из
`.env.stage`. Один Telegram-токен нельзя одновременно использовать в двух
polling-процессах: Telegram ответит `409 Conflict`.

Если stage сообщает о втором процессе, проверьте PID из `.stage-bot.pid`. Если
PID уже не существует, удалите только этот устаревший PID-файл и запустите
`make stage` снова.

## Production

Целевая структура каталогов и первый переход на версионный деплой описаны в
[`deploy/README.md`](deploy/README.md). Production-сервис должен работать от
пользователя `tg-poll-bot`, а `.env`, состояние, health-файл и логи должны
находиться в `/opt/bot_tg/shared`.

Основные проверки:

```bash
systemctl is-active tg-poll-bot
systemctl status tg-poll-bot --no-pager
journalctl -u tg-poll-bot -n 100 --no-pager
/opt/bot_tg/current/venv/bin/python /opt/bot_tg/current/deploy/check_bot_health.py
```

`systemctl is-active` подтверждает наличие процесса. Прикладной health-check
дополнительно проверяет свежий успешный запрос к Telegram API и работающий
планировщик.

## Состояние и восстановление

Рабочее состояние хранится в `shared/state.json`. Каждая успешная перезапись
создаёт `shared/state.json.bak`; оба файла имеют права `600`.

Если основной JSON повреждён, бот при запуске автоматически читает резервную
копию и пишет предупреждение в журнал. После этого:

1. Остановите сервис, чтобы состояние не менялось во время проверки.
2. Сохраните копии `state.json` и `state.json.bak` вне рабочего каталога.
3. Проверьте JSON командой `python3 -m json.tool`.
4. Если основной файл повреждён, замените его проверенной резервной копией.
5. Восстановите владельца `tg-poll-bot:tg-poll-bot` и режим `600`.
6. Запустите сервис и проверьте `/status`, журнал и health-check.

Не редактируйте `state.json` при работающем боте: следующий update может
перезаписать ручные изменения.

## Откат релиза

`deploy/install_release.sh` автоматически возвращает предыдущий `current`, если
новая версия не записала свежий heartbeat. Для ручного отката переключите
`/opt/bot_tg/current` на предыдущий каталог из `releases`, перезапустите сервис
и выполните health-check. `shared/state.json` не откатывается вместе с кодом;
перед изменением схемы состояния всегда нужна совместимая миграция.

## Диагностика частых сбоев

- `409 Conflict`: другой процесс получает updates с тем же токеном. Найдите и
  остановите именно лишний экземпляр.
- Сервис active, health-check падает: проверьте свежесть `health.json`, доступ к
  Telegram API, прокси и статус scheduler в JSON.
- Бот не пишет в чат: проверьте `CHAT_ID`, права бота и последние ошибки через
  `journalctl`.
- После рестарта нет ожидаемой задачи: проверьте timezone и сохранённое
  расписание; при запуске бот выполняет согласование пропущенных задач.
