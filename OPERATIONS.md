# Эксплуатация бота

## Проверка перед выпуском

```bash
make lint
make coverage
```

Для ручной проверки можно создать `.env.stage` из `.env.stage.example` и
запустить `make stage`. Stage нужен только для изменений поведения Telegram;
для небольших внутренних правок достаточно автоматических тестов.

## Production

Бот находится в `/opt/bot_tg` и запускается сервисом `tg-poll-bot`.

```bash
systemctl status tg-poll-bot --no-pager
journalctl -u tg-poll-bot -n 100 --no-pager
/opt/bot_tg/venv/bin/python /opt/bot_tg/deploy/check_bot_health.py
```

При push в `main` GitHub Actions выполняет тесты, копирует файлы в
`/opt/bot_tg`, перезапускает сервис и ждёт свежий heartbeat. Если бот не
запустился, workflow завершается ошибкой и выводит последние записи журнала.

## Уведомления о связи с Telegram

Проверка API выполняется каждую минуту. После трёх неудачных проверок подряд
бот пытается предупредить каждого администратора. Повторная попытка для того
же администратора выполняется не чаще раза в час, в том числе если отправка
завершилась таймаутом. При продолжающемся сбое попытки повторяются раз в час.

Сообщение о восстановлении отправляется после трёх успешных проверок подряд
и только администраторам, для которых API подтвердил отправку предупреждения.
Если отправка восстановления не удалась, повторная попытка возможна через час
при устойчивой связи. После успешной отправки повторов нет до следующего
доставленного предупреждения. Единичный сбой сбрасывает счётчик успешных проверок.

Счётчики, время попыток и сведения о доставленных предупреждениях сохраняются
в `health.json` и переживают перезапуск. Heartbeat отражает результат последнего
запроса сразу, не дожидаясь трёх успехов. В журнале фиксируются тип ошибки и
число последовательных неудач; токены и содержимое запросов не записываются.

## Состояние опроса

Опрос и расписание хранятся в `/opt/bot_tg/state.json`. Перед каждой успешной
перезаписью бот сохраняет предыдущую версию в `state.json.bak`. Если основной
файл повреждён, резервная копия читается автоматически.

Не редактируйте `state.json` при работающем боте. Для ручного восстановления
остановите сервис, проверьте резервную копию командой `python3 -m json.tool`,
замените повреждённый файл и снова запустите сервис.

Ошибка Telegram `409 Conflict` означает, что тот же токен уже используется
другим polling-процессом. Нужно найти и остановить именно лишний экземпляр.
