## Что делает бот

- В **среду и воскресенье в 09:50 МСК** автоматически создаёт неанонимный опрос "Идете?" в чате
- Закрепляет опрос с уведомлением участников
- Сразу после создания опроса пишет подсказку: можно написать `+1 Фамилия`, и бот добавит приглашенного в общий учет
- При **9 голосах "ДА"** пишет в чат: "Братики, еще 1 и идем 💪"
- При **10 голосах "ДА"** пишет в чат: "Ну все, епта, идем играть, готовьтесь 🔥"
- После достижения 10 голосов сообщает о каждом снятом голосе; если остаётся меньше 10 — предупреждает, что людей снова не хватает
- В **15:00 МСК** если порог не набран — уведомляет админов
- В **20:00 МСК** автоматически закрывает опрос и очищает состояние
- В **среду 19:45** и **воскресенье 18:15** МСК — если 10+ ДА — пишет в чат: "Мужчины, напоминаю что сегодня вы играете..."
- Сохраняет состояние в `state.json` — после перезапуска помнит все голоса
- Команды для админов: `/poll` (запуск вручную), `/announce` (бот попросит следующий текст и опубликует его от своего имени), `/cancel` (отменить ввод объявления), `/plus1` (добавить виртуальный голос), `/minus1` (убрать последний виртуальный голос), `/settime` (изменить время), `/setdays` (изменить дни недели)
- Команды для всех: `/start`, `/status` (текущий счёт)

## Конфигурация (.env)

```
BOT_TOKEN=<токен от @BotFather>
CHAT_ID=<id группового чата>
ADMIN_ID=<telegram id главного админа>
EXTRA_ADMIN_IDS=<telegram id доп. админов через запятую>
TIMEZONE=Europe/Moscow
YES_THRESHOLD=10
POLL_QUESTION=Идете?
DATA_DIR=/opt/bot_tg
LOG_MAX_BYTES=5242880
LOG_BACKUP_COUNT=3
ANNOUNCE_TTL_SECONDS=300
POLL_RECONCILE_DELAY_SECONDS=0.5
HEALTHCHECK_INTERVAL_SECONDS=60
HEALTH_FAILURE_THRESHOLD=3
```

Логи пишутся в `bot.log` с ротацией: по умолчанию 5 МБ на файл и 3 архивные копии.
Шумные HTTP-логи библиотек `httpx/httpcore/telegram` приглушены до `WARNING`, чтобы не писать каждый polling-запрос и не раздувать диск.

## Управление расписанием (без перезапуска)

Админ может менять расписание прямо из бота:

```
/settime               — показать текущее расписание
/settime poll 09:50    — время запуска опроса
/settime deadline 15:00 — время дедлайн-уведомления
/settime close 20:00   — время закрытия опроса
/settime remind_wed 19:45 — напоминание в среду
/settime remind_sun 18:15 — напоминание в воскресенье

/setdays poll wed,sun        — дни запуска опроса
/setdays remind_wed wed,fri  — дни напоминания
```

Допустимые значения дней: `mon tue wed thu fri sat sun` (через запятую, без пробелов).  
Изменения вступают в силу **сразу** и сохраняются в `state.json` (переживают рестарт).

## Виртуальные `+1` от админа

Нативный счётчик Telegram-опроса бот изменить не может: Telegram сам присылает агрегированные числа и управляет UI самого poll.

Поэтому добавлены отдельные виртуальные голоса, которые влияют на логику бота:

```bash
/plus1
/plus1 Паша
/minus1
/minus1 Паша
/status
```

В рабочем чате также работают короткие текстовые сообщения без slash-команды:

```text
+1
+1 Иванов
-1
```

- `/plus1` добавляет виртуальный `+1`
- `/plus1 Паша` добавляет виртуальный `+1` с подписью
- `/minus1` убирает последний виртуальный `+1`
- `/minus1 ФИО` убирает конкретного приглашённого
- `/status` показывает отдельно реальные голоса из Telegram и виртуальные голоса
- любой участник чата может написать `+1 Фамилия`, и бот сохранит фамилию приглашенного вместе с виртуальным голосом
- сообщение без фамилии — строгое `+1` — сохраняется как `Гость от Имя отправителя`
- фразы вроде `Со мной идет +1` или `+ 1 Иванов` бот игнорирует
- после такого сообщения бот отвечает, кто добавлен, и показывает текущую сводку по `ДА/Нет`
- `-1` обычным сообщением по-прежнему доступен только админам

Виртуальные голоса:
- участвуют в пороге `YES_THRESHOLD`
- учитываются в дедлайне и напоминаниях
- сохраняются в `state.json` и переживают рестарт
- хранят имя добавившего участника, время добавления и источник команды

Ограничение: цифра внутри самого Telegram-опроса визуально не меняется.

## Stage тест без остановки прода

Цель: пользователи продолжают работать на прод-боте, а админ тестирует новую версию отдельно.

1. Создайте отдельного Telegram-бота в BotFather (stage token).
2. Создайте отдельный тестовый чат для stage.
3. Подготовьте локальный env:

```bash
cp .env.stage.example .env.stage
# заполните BOT_TOKEN/CHAT_ID/ADMIN_ID
```

4. Запуск локального stage-бота:

```bash
make setup
./run_stage.sh
```

> `run_stage.sh` не запустит второй локальный экземпляр, если первый ещё работает.
> Не запускать `venv/bin/python main.py` напрямую — если процесс уже висит, будет конфликт polling (409).

Что важно:
- `ENABLE_SCHEDULER=0` в stage отключает cron-задачи, чтобы тестировать руками через `/poll`.
- Не запускайте одновременно прод и локальный stage с одним и тем же токеном.
- В проде оставляйте обычный `.env`.

Быстрый цикл релиза:
1. Тест фичи локально на stage-боте.
2. Коммит и push в `main`.
3. Автодеплой обновляет прод.

## Как работаем с Copilot

Этот раздел нужен, чтобы после прерывания или новой сессии не договариваться заново.

1. Вы пишете задачу по изменению бота.
2. Copilot вносит правки локально в проект.
3. Запуск и проверка делаются в stage-режиме (`.env.stage`), без остановки прода.
4. Вы проверяете поведение в тестовом чате.
5. После вашего подтверждения (`ок в прод`) изменения уходят в `main`.
6. GitHub Actions деплоит на сервер и перезапускает прод-бота.
7. Copilot проверяет, что сервис `tg-poll-bot` в статусе `active`.

Правило безопасности:
- новые/рискованные фичи сначала stage, потом прод;
- прод не останавливаем для обычной разработки.
