# tg-poll-bot

Telegram-бот для групповых опросов: считает голоса, учитывает приглашённых
через `+1`, сообщает о наборе и потере кворума, отправляет напоминания.
Работает на Python 3.12; зависимости закреплены в `requirements.txt`.

## Где что лежит

```text
app/        — код бота, обработчики, расписание и хранение состояния
scripts/    — запуск локального тестового бота
tests/      — автоматические проверки
deploy/     — systemd-сервис и проверка состояния
.github/    — CI и автодеплой
```

`app/bot.py` собирает приложение; остальные модули отвечают за голоса,
объявления, настройки, расписание и сохранение данных. Точка входа —
`app/__main__.py` (`python -m app`).

## Локальная работа

```bash
make setup
make lint
make coverage
```

Для ручной проверки создайте **отдельного** бота и тестовую группу:

```bash
cp .env.stage.example .env.stage
# Заполните токен, CHAT_ID и ADMIN_ID в .env.stage.
make stage
```

Stage запускается с `ENABLE_SCHEDULER=0`; команды проверяются вручную.
Скрипт защищает от повторного запуска того же локального stage-процесса.
Не используйте один токен одновременно на двух серверах или в stage и production:
это вызывает конфликт polling (`409 Conflict`).

При запуске из корня проекта команда `venv/bin/python -m app` читает `.env`.
`ENV_FILE` позволяет указать другой файл. Образцы настроек:
[production](.env.example) и [stage](.env.stage.example).
Настоящие токены в Git не добавляются.

## Команды и расписание

Для всех: `/start`, `/status`. Для администраторов:

| Команда | Действие |
|---|---|
| `/poll` | Создать опрос вручную |
| `/announce`, `/cancel` | Опубликовать следующий текст от бота или отменить ввод |
| `/plus1 [имя]`, `/minus1 [имя]` | Добавить или убрать виртуальный голос |
| `/settime` | Показать расписание |
| `/settime poll 09:50` | Изменить время опроса |
| `/setdays poll wed,sun` | Изменить дни опроса |

Для `/settime` доступны `poll`, `deadline`, `close`, `remind_wed`, `remind_sun`;
для `/setdays` — те же ключи. Дни: `mon,tue,wed,thu,fri,sat,sun`.
Настройки применяются сразу и сохраняются в состоянии.

Любой участник рабочего чата может написать `+1`, `+1 Фамилия` или `+1Фамилия`.
Без подписи сохраняется «Гость от Имя». Команда `-1` доступна администраторам.
Ручные голоса участвуют в кворуме, но цифру внутри Telegram-опроса изменить нельзя.
`/status` показывает реальные и виртуальные голоса отдельно.

По умолчанию опрос создаётся в среду и воскресенье в 09:50 МСК,
дедлайн — 15:00, закрытие — 20:00. Напоминания: среда 19:45 и воскресенье 18:15
при набранном кворуме. **Сохранённое расписание имеет приоритет над этими значениями.**
По умолчанию кворум — 10: при 9 бот просит ещё одного участника,
при 10 сообщает о наборе, затем отслеживает отказы и потерю кворума.

## Сервер и автодеплой

Каталог на сервере — `/opt/bot_tg`, окружение — `venv/`, сервис — `tg-poll-bot`.
Сервис запускает `venv/bin/python -m app` из каталога проекта.
`.env`, `state.json`, `health.json` и `bot.log` находятся в каталоге данных:
по умолчанию это корень проекта; `DATA_DIR` задаёт другой путь.

```bash
systemctl status tg-poll-bot --no-pager
journalctl -u tg-poll-bot -n 100 --no-pager
/opt/bot_tg/venv/bin/python /opt/bot_tg/deploy/check_bot_health.py
```

Новый VPS — `178.62.199.241` (Амстердам). Цель GitHub Actions задают
секреты `VPS_HOST`, `VPS_USER`, `DEPLOY_KEY`. Push в `main` запускает
проверки, копирование `app/` и файлов деплоя, установку зависимостей
и проверку синтаксиса. `.env` и состояние при этом не перезаписываются.

**Деплой запускает или перезапускает бота только при наличии файла
`/opt/bot_tg/.allow-deploy-start` на сервере.** Без него файлы обновляются,
бот остаётся выключенным. Описание systemd-сервиса обновляется без запуска.
Если без разрешения сервис уже работает,
workflow завершается ошибкой без перезапуска.
При разрешённом запуске проверяется свежий heartbeat.

При переносе сначала остановите старый polling-процесс, повторно скопируйте
актуальное состояние и только затем разрешайте запуск нового.
Подготовленная заранее копия состояния — снимок; автоматически она не синхронизируется.
Первое включение и публикация локальных изменений выполняются по команде владельца.

## Сохранение данных

`state.json` хранит опросы, голоса и расписание. Запись атомарная;
предыдущая версия сохраняется в `state.json.bak` и используется при повреждении
основного файла. Не редактируйте состояние при работающем боте.
Для ручного восстановления остановите сервис, проверьте JSON резервной копии
и замените основной файл.

Лог ротируется: по умолчанию 5 МБ и 3 архивные копии.
HTTP-логи библиотек приглушены до `WARNING`.

## Проверка связи с Telegram

Проверка API выполняется при запуске бота, затем в начале каждого часа.
В дни опросов (из текущего `/setdays poll`, по часовому поясу бота) добавляются
проверки в :15, :30 и :45. Изменение дней применяется сразу без перезапуска.
Старая переменная `HEALTHCHECK_INTERVAL_SECONDS` больше не используется.
CLI-проверка допускает возраст heartbeat до 65 минут (3900 секунд);
`BOT_HEALTH_MAX_AGE_SECONDS` позволяет задать свой предел.
После трёх неудачных проверок подряд
бот пытается предупредить каждого администратора. Повторная попытка для того
же администратора выполняется не чаще раза в час, в том числе если отправка
завершилась таймаутом. При продолжающемся сбое попытки повторяются раз в час.

Сообщение о восстановлении отправляется после трёх успешных проверок подряд
и только администраторам, для которых API подтвердил отправку предупреждения.
Если отправка восстановления не удалась, повторная попытка возможна через час
при устойчивой связи. После успешной отправки повторов нет до следующего
доставленного предупреждения. Единичный сбой сбрасывает счётчик успешных проверок.

Счётчики, время попыток и сведения о доставленных предупреждениях сохраняются
в `health.json` и переживают перезапуск. Heartbeat отражает результат последнего
запроса сразу, не дожидаясь трёх успехов. В журнале фиксируются тип ошибки и
число последовательных неудач; токены и содержимое запросов не записываются.
